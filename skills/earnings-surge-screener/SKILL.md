# 业绩兑现痕迹×景气表述筛选与前瞻选股

三阶段+一条逆向轨的工作流。Track A 找"业绩大增且亲口说景气"的公司，输出经板块景气确认评分（`references/sector-confirmation.md`）定级主线板块后进入阶段二；Track B 补捞"仅有初步兑现痕迹"的拐点期公司；Track C 逆向筛选"业绩向好但被市场风格/行业β错杀"的低位成长股，启动前先过吸血环境确认闸门，环境不满足时降级只出排雷结果；阶段二判断"股价是否已定价、景气能否持续"（Track C 候选按镜像解读过同一框架）。三轨共用通用筛选层（两道闸门 + 三个分档维度 + 言行合一检验，见 `references/quality-gates.md`）。数据走 Gildata（agent-gw）与 Wind，行业周期用 web 搜索验证。

## 指定对象路由层（用户点名个股/板块时，先于一切轨道执行）

### 点名个股

用户点名具体股票（一只或多只）要求分析/买入建议时，**禁止直接默认某条轨道**——先对每只个股并行校验三轨入池条件，输出路由判定表后再分流。全市场筛选请求不适用本节，直接按用户意图选轨。

| 个股 | Track A（增速≥50%或扭亏 + 景气表述） | Track B（五类痕迹命中） | Track C（三锚 + 环境闸门） | 路由结果 |
|---|---|---|---|---|

路由规则：

1. **逐条校验，命中即路由**：按各轨 reference 的阈值逐条核对（数据缺失标"待补查"，不猜）；命中 Track A → 走阶段一后半段（通用闸门 + 阶段二）；命中 Track B → 按痕迹类型与证据分级执行；命中 Track C → 先过环境确认闸门再走三锚与四维排雷；
2. **多轨可同命中**：标注双轨身份，阶段二按主轨（证据更强者）执行，副轨结论并列呈现；
3. **零命中兜底**：三轨皆不命中但通用两闸门通过且净利润增速 ≥20% → 直送阶段二三维框架，标"直评"，报告中写明"不属于任何轨道，按三维框架直接评估"；两闸门不过 → 直接输出排除结论与原因；
4. **失败条件显性化**：每条未命中的轨道写明具体卡在哪条（如"背离锚：YTD 为正且未跑输基准"）——个股不得无声消失，"不符合"与"数据待补"分开表述。

### 点名板块

用户点名具体板块（如"筛选锂电池板块""分析机器人板块"）时，**禁止只跑 Track A 一条轨**，按以下规则分流：

1. **创新药板块（含CXO）**：整体走 `references/innovative-drug-framework.md` 统一框架（现有规则不变），本节其余条款不适用；
2. **其他板块**：在板块成分股内并行执行三轨口径——
   - **Track A 口径**：检索该板块公司当期业绩预告/半年报/公告，按双因子（增速≥50%或扭亏 × 景气表述）筛选；
   - **Track B 口径**：板块本身即锚（用户点名视同板块锚），按五类痕迹扫描成分股；若板块正因某产业事件被点名，注明事件→板块传导链；
   - **Track C 口径**：先过环境确认闸门，再在板块内按三锚筛选（背离锚两层拆解相应变为：个股 vs 板块指数、板块指数 vs 沪深300）；
3. **板块级判定**：对点名板块执行 `references/sector-confirmation.md` 四因子评分，输出该板块定级（主线候选/景气验证中/个案）——**用户点名的板块不等于已确认景气**，定级结论须明确告知；定级为"个案"的板块，其 Track B 候选证据等级上限 ★，并写明"板块景气未获确认"；
4. **输出**：三轨候选分层并列（标注轨道与证据等级，不混排）+ 板块定级结论；各轨内部零命中个股不进名单、不逐家罗列；
5. **板块边界**：概念板块（如"机器人""AI应用"）用概念成分股，申万行业用行业成分；用户给的范围过宽（如"科技股"）时先按细分行业拆分或请用户收窄，不在过宽范围内海选。

## 数据源路由

- **Gildata 走 kimi-datasource 插件（MCP）**：调用 `mcp__plugin-kimi-datasource_data__call_data_source_tool`,`data_source_name="gildata"`,`api_name` 取下列之一，`params` 固定为 `{"query": "<自然语言>", "file_path": "<绝对路径 csv>"}`。首次使用前先 `get_data_source_desc("gildata")` 核对 API 清单。常用 API:`gildata_announcement_data`（公告原文）、`gildata_smart_stock_selection`（选股）、`gildata_fin_query`（估值/区间行情/一致预期）、`gildata_financial_research_report`（研报）、`gildata_news_data_query`（新闻舆情）。
- **脚本一律 `uv run python`**（本系统 uv 管理环境，pandas 已在依赖内）。
- **`gildata_fin_query` 调用口径（唯一来源）**：单次调用最多 3 个明确实体（公司），超限报 PARAMETER_ERROR「单次调用最多支持 3 个明确实体」；批量补查一律按 3 家一组拆 call。每次只问一个指标主题（可跨多期，如"2026年与2027年一致预期净利润"算一个主题）；同句塞多个指标易被识别为更多实体而拒绝（2026-07-30 实测：10 家一批、3 家×7 指标、3 家×2 行情指标均被拒，3 家×1 指标稳定成功）。**`gildata_announcement_data` 同样卡 ≤3 个明确实体**（2026-08-15 实测：行业词列表触发 PARAMETER_ERROR），检索查询避免罗列多个公司/行业专名。
- **选股兜底**：语义选股（`gildata_smart_stock_selection`）EMPTY_DATA 或命中质量差时，放宽阈值/换措辞重试；本环境无 Wind 选股端点（kimi-datasource 的 wind 仅分钟线/基金/债券），不做其他兜底。
- **结果表解析（强制用脚本，禁止手写解析器）**：`uv run python scripts/parse_gildata_table.py <csv> [--cols 列1,列2]`，把 Gildata 返回 CSV 中内嵌的 markdown 表解析成干净表格（区间行情/一致预期/估值表都用它）。2026-07-31 实测：在 ipython 里手写 inline 解析连续两轮失败——table_markdown 中字面 `\n` 与真实换行混杂（只按真实换行切会吞掉表头行）、且存在列数不齐的脏行（38≠39 列直接抛 AssertionError）；本脚本已处理这三点（同时切两种换行、剔除分隔行、丢弃列数不齐行）。需要 DataFrame 时一律 `--out` 存 CSV 再 `pd.read_csv`，不要重写解析器。
- **纪要信心检索**：`gildata_announcement_data` 查"{公司} 投资者关系活动记录表"/"{公司} 业绩说明会"原文，`gildata_financial_research_report` 查调研类研报中管理层口径转述——检索顺序与信心信号分级口径以 `references/quality-gates.md` 言行合一检验为唯一来源。
- 每个数据点必须带 `[Source: ... — ..., as of ...]` 引用；公告原话、券商观点、自己的推断三者分开表述。
- **中间 CSV 落盘**：查询结果存 `data/raw/gildata/{api 短名}/{YYYY-MM-DD}/<主题>.csv`(与本系统 raw 留痕约定一致，便于复核与重跑）;scratch 文件可用 /tmp，但最终作为证据引用的 CSV 必须落 `data/raw/gildata/`。

## 与本系统的衔接（trade 监测管线）

本 skill 是**选股研究层**，产出只进人工决策，不进确定性管线：

1. **候选交接**:Track A/B/C 与阶段二产出的核心候选（S级/第一梯队/C1)，经人工确认后→加入 `config/watchlist.yaml` → 用 `stock-collect` skill 采集历史数据 → 用 `fred-valuation-card-skill` 生成估值排期卡 draft → 人工激活后由每日管线跟踪。LLM 不产生规范化数字、排期卡 activate/reject 必须人工，两条纪律不变。
2. **报告落盘**：筛选报告存 `reports/screening/YYYY-MM-DD-<主题>.md`，含跟踪清单与事后校验记录（本 skill 输出纪律一节不变）。
3. **证伪信号→提醒**：核心候选的证伪信号经用户确认后转为 cron 提醒（CronCreate)，触发后按跟踪重检层执行重检；每日盘后管线（`scripts.pipeline.daily`）自动覆盖 watchlist 内候选的行情/指标/信号。
4. **执行留痕**：每次筛选执行后追加 `docs/execution_log.md`（查询、命中数、入选候选、档位）。

## 通用筛选层（三轨共用）：两道闸门 + 三个分档维度 + 言行合一检验

**细则、阈值与分轨口径统一以 `references/quality-gates.md` 为唯一来源，各轨执行时必读；本节只给逻辑骨架，不重复数值。**

1. **闸门一 业绩质量（淘汰性）**：营收印证利润，防低基数/并表/补贴/费用压缩堆出的假性增长；分轨口径不同，利润暴增但营收印证不足者标"利润质量待验证"，只进观察档。
2. **闸门二 增长驱动分型（强制标注，输出用汉字）**：扩张型（新产品/新服务/新市场，加分）/ 景气型（量价齐升）/ 周期型（纯涨价，阶段二必须答周期位置）/ 非经常型（低基数/并表/补贴，原则排除）。读公告原因段与纪要归因，证据不足标"未分型"，不猜；扩张型/景气型须按 quality-gates.md 量化验证口径做数据交叉验证，仅文字表述者标"分型待验证"。
3. **分档维度（分档非淘汰）**：低位程度 × 机构筹码（存量拥挤度 × 增量趋势）× 产业趋势强度——只决定升降档，不做淘汰；纯β搭车不得进核心档。
4. **言行合一检验（管理层表态信号分级，三轨通用）**：口头乐观 + 硬信号（增持/回购/高行权条件股权激励/大额扩产/长期锁量协议）→ 升档加分；口头乐观 + 减持/零扩产等背离 → 不得进核心档；纪要表态只作软信号（按强/中/套话三级分级后使用），输出须声明"管理层表态天然乐观"偏差。细则见 quality-gates.md。
5. **创新药板块**：仅部分参照，适用边界以 `references/innovative-drug-framework.md` 第一节为唯一来源。

## 阶段一（Track A）：双因子筛选（业绩大增 × 景气表述）

1. **关键词组检索**：按 `references/keyword-taxonomy.md` 第二节的 6-8 组查询模板，逐组调 `gildata_announcement_data` 检索当期业绩预告/半年报公告，各存一个 CSV。报告期按当前日期推算（7-8 月=半年报、1 月=年报预告、4 月/10 月=季报）。
2. **正则二次核验**：`uv run python scripts/verify_announcements.py '/tmp/ann_*.csv' --min-growth 50 --out /tmp/verified.csv`。语义检索是模糊命中，此步不可省——它做八组关键词正则核验（体系见 references/keyword-taxonomy.md 第一节）、提取净利润增速区间、剔除预亏预降。
3. **人工复核边界**：增速贴线、利润绝对额过小、或增速异常高的公司，回看公告原文确认（防订单/营收增速误判、防低基数幻觉；**扭亏命中额外确认"扭亏为盈"的主语是公司整体而非某业务分部**——分部扭亏但公司整体净利润仍下降的为假阳性，剔除；边界口径见 references/keyword-taxonomy.md 第三节）。
4. **通用闸门**：按 `references/quality-gates.md` 执行闸门一（业绩预告常缺营收，入池后用 `gildata_fin_query` 按 3 家×单指标分批补查，口径见「数据源路由」）与闸门二（增长驱动分型强制标注）。
5. **重点公司补查**：对知名但检索遗漏的公司（龙头常被表格型公告漏抓），单独发公告查询补齐增速与原因。
6. **按板块聚合输出**：公司 | 细分 | 增速 | 营收增速 | 增长驱动型 | 命中关键词 | 公告核心原话 | 披露日期。
7. **板块景气确认评分**：按 `references/sector-confirmation.md` 对命中板块做四因子评分（命中密度×业绩一致性×周期位置×行情确认度），输出板块排序表并定级（主线候选/景气验证中/个案）——阶段二只从"主线候选"与"景气验证中"板块取池；
8. **选池进阶段二**：每细分板块取增速与关键词证据最强的 ≤5 家进入阶段二（"景气验证中"板块减半至 ≤2-3 家，"个案"板块入选个股须注明板块证据为个案），总候选 ≤25 家；超出时按"增速下限优先、命中关键词组数次之"排序截断，被截断者留在明细表、不进前瞻分析。

## 阶段1.5：Track B 早期痕迹层（初步兑现但尚未大增）

Track A 必然漏掉"拐点确认期"的公司。执行细则（范围控制、四类痕迹阈值、证据分级、固有风险）见 `references/track-b-signals.md`，做 Track B 前必读。要点：

1. **锚定范围**：只从板块景气确认评分定级的"主线候选/景气验证中"板块 + 搜索验证的涨价品种 + 产业事件锚（重大技术迭代/政策转向/海外映射后 3-6 个月内定向扫描，须写明事件→板块传导链）里找候选，禁止全市场海选；
2. **五类痕迹**（命中即入池，判定阈值见细则）：B1 单季拐点（净利润同比与环比双改善，且同季营收同比为正——闸门一口径，利润增营收降者证据降一级）；B2 合同负债/在手订单/毛利率等先行指标异动；B3 券商一致预期近期显著上调（唯一允许脱锚全市场扫描的痕迹，★ 级起步）；B4 确认板块内滞涨但有自身订单/产能证据的扩散标的；B5 底部信号（连续两季亏损收窄或毛利率触底回升且营收止跌，背景须行业指数深跌企稳，默认 ★ 级）；全部入池候选按 quality-gates.md 标注闸门二增长驱动分型；
3. **证据分级输出**：★★★（预告大增）/ ★★（拐点+先行指标双印证）/ ★（仅板块扩散），★ 级只进观察名单并写明待验证事项；
4. 常用选股查询模板见 track-b-signals.md 四类痕迹表"查询方式"列。

## 阶段1.6（Track C）：β错杀轨（业绩向好但被市场风格错杀）

Track A/B 赚"景气扩散"的钱（顺势），Track C 赚"定价修复"的钱（逆向）：筛选财报业绩向好、但被行业β/市场风格无差别抛售错杀的非景气行业成长股。本轨是"错杀成长股轨"而非烟蒂轨——目标是"成长性好但被杀估值"，不是"盈利稳定的深度低估"。执行细则（三重锚定阈值、四维排雷、催化剂清单、镜像四档、固有风险）见 `references/track-c-oversold.md`，做 Track C 前必读。要点：

1. **环境确认闸门**（先于锚定，决定运行模式）：TMT/AI 板块成交占比近一年分位 >70% 且非主线行业成交持续萎缩，或领涨主线指数与候选行业指数 YTD 差 >30pct——二者满足其一才确认吸血环境；不满足（普涨/普跌/无吸血主线）时本轨降级，只输出 C3/C4 排雷结果，不推荐 C1/C2；
2. **三重锚定**（禁止全市场无锚海选，候选 10-30 家，超额排序截断规则见细则）：业绩锚（利润增长 + 扣非占比高 + 经营现金流为正 + 营收为正）× 背离锚（股价与业绩显著背离，按个股 vs 行业指数、行业指数 vs 沪深300 两层拆解，须先判市场状态）× 估值锚（PE/PB 历史分位极低）——三者相乘，估值分位是区分"涨多了的正常回调"与"真错杀"的关键闸门；
3. **四维排雷**（错杀 vs 价值陷阱甄别，本轨核心）：业绩质量（防假业绩）× 下跌归因分离（行业β普跌 vs 公司个体利空）× 行业性质（周期性低迷可修复 vs 结构性衰退不可修复）× 持续性（次年一致预期方向；为负=市场可能是对的=价值陷阱）；
4. **修复催化剂跟踪**：公司层（回购/大股东增持/提高分红率——低估值下公司自己拿钱投票是最强信号）、行业层（库存周期拐点、价格战缓和、政策转向）、市场层（拥挤板块资金高低切换）；
5. **镜像四档输出**：C1核心候选（三锚全中+排雷全过+催化剂已现）/ C2观察（催化剂未现，等右侧）/ C3价值陷阱排除（明确"不要碰"，本轨最有价值的输出）/ C4下跌合理回避（跌因自身恶化）；
6. **衔接规则**：阶段二镜像解读统一以 `references/forward-framework.md` 第六节为唯一来源；命中的创新药/CXO 标的按 `references/innovative-drug-framework.md` 第一节混池路由处理；候选按 quality-gates.md 标注增长驱动分型（非经常型原则排除）；
7. **纪律声明**：本轨为左侧交易，信号噪声比天然差于顺势轨，必须输出分批建仓/右侧确认纪律与"市场定价可能是对的"反向风险提示。

## 创新药行业模块：统一评估框架（目标板块为创新药时启用，替代阶段1.5/1.6的默认流程）

当筛选目标为创新药板块（含CXO）时，**必读并执行** `references/innovative-drug-framework.md`。行业闸门、混池路由与通用筛选层适用边界以该文件第一节为唯一来源，要点：

1. **行业闸门**：仅创新药板块适用（创新药概念成分，或主业创新药研发/授权/CXO服务；申万医药生物仅作初筛线索，中药/医药商业/医疗器械/医疗服务不适用）；其他行业一律禁用，走默认流程；
2. **混池路由**：用户指定创新药板块 → 整体走统一框架；全市场轨道混合池中命中的个别创新药/CXO 公司不剥离，随大池走默认轨道，但一次性利润拆分归型与风险底线回引该文件；
3. **价值驱动四分型**：盈利兑现型/利润失真型（先按拆分规则归型）/管线期权型/CXO服务传导型——分型只决定证据类型，不改变评估流程；
4. **统一四维评分卡 × 统一分级 × 单表输出**：兑现度 × 前瞻动能 × 定价锚 × 风险底线，评分与分级规则、固定列总表见该文件第三至五节，不按维度拆分子表；证据级 ★★★/★★/★ 沿用。

## 阶段二：三维前瞻分析

框架细则、三维评分刻度、四档决策矩阵、行业周期判断要点见 `references/forward-framework.md`，执行前必读。步骤：

1. **兑现度**：`gildata_fin_query` 拉候选公司年初至今区间涨跌幅、区间最高/现价回撤。
2. **持续性**：`gildata_fin_query` 拉当年+次年一致预期净利润（3 家一组、单指标主题分批，口径见「数据源路由」）；次年增速方向是第一分水岭。
3. **行业周期验证**：web 搜索主要板块的供需缺口持续性、新产能释放时点、价格斜率（每板块 1 次查询）；按 references/forward-framework.md 第三节的分行业要点解读；政策驱动型板块另按该文件第七节做政策×产能周期矩阵定位，落"死亡象限"者持续性维度降级。
4. **通用分档维度叠加**：低位程度（与维度1数据共用）× 机构拥挤度 × 产业趋势强度——口径与阈值以 `references/quality-gates.md` 为准。
5. **催化剂日历排序**：同档内按"最近可验证催化剂距离"排序（维度4 刻度见 forward-framework.md 第一节：财报窗口/产能投产/订单放量/政策节点/价格拐点预期月/公司层事件），最近催化剂时点即跟踪清单"下次重检时点"的默认取值；维度4 只排序不淘汰；
6. **S级+四档分层输出**：三维各按优/良/中/差评分后经决策矩阵定档：S级（超级α核心候选，七项判定清单全中，清单见 forward-framework.md 第二节）/ 第一梯队（核心候选）/ 第二梯队（部分兑现）/ 高危警示（周期顶陷阱）/ 已透支回避；S级是分层而非淘汰，未全中者维持原档不降。创新药标的按 innovative-drug-framework.md 第一节混池路由处理，license-out 型公司经拆分归型后再定性，不得直接贴周期顶标签。
7. **证伪信号表**：每个推荐方向给核心假设+可跟踪的证伪信号（模板见框架文件第四节），其中产业趋势假设须给出趋势级证伪条件。
8. **Track C 衔接**：Track C 候选同样过本框架，兑现度镜像解读、前瞻估值改为"历史分位+绝对PE+股息率"三重锚——规则统一见 references/forward-framework.md 第六节。

## 跟踪重检层（把证伪信号变成跟踪任务）

选股不是一次性产出：每个核心候选（S级 / 第一梯队 / C1 / 创新药核心候选）交付时必须附**跟踪清单**（聊天内可简写，报告文件固定一节）：

| 候选 | 核心假设 | 证伪信号（触发即重检） | 检查频率 | 下次重检时点 |

- **频率口径**：行业高频价格/订单数据 → 周度；公司经营数据 → 月度；财报/业绩预告 → 季度（披露窗口前重检）；催化剂事件（回购、增持、临床读出、签约）→ 事件驱动即时；
- **重检动作**：信号未触发 → 维持档位，仅更新数据；触发 → 只重过受影响维度（如行业价格破位 → 重过持续性维度；回购终止 → 重过催化剂与档位），给出升/降档结论，不全量重跑；
- **提醒衔接**：若用户有定时提醒机制（cron），主动建议把核心候选的证伪信号转为提醒条件（如"六氟价格跌破 X 万即提醒"），提醒触发后按上条执行重检；
- **事后校验（预测校准回路）**：每个核心候选在证伪信号触发、档位调整/排除、或入选满 6/12 个月时，在报告文件追加一行"信号→表现"对照：候选 | 入选档位与日期 | 信号类型（扩张/景气/周期/错杀/B 类痕迹编号/S级） | 触发或到期事件 | 期间相对沪深300 超额收益 | 结论（信号有效/失效/待观察）。累积样本用于回看哪类信号胜率高，作为后续档位权重与阈值微调依据——只调权重与阈值，不轻改架构。S 级候选须单独累计样本：七项全中组合是否跑赢普通第一梯队，用 6/12 个月超额收益数据校准七项标准的取舍与权重——标准本身同样可证伪。

## 输出与纪律

- 交付物：聊天内分层结论表 + 板块排序表（Track A 执行时必备） + Markdown 报告文件（方法、板块排序、总览、明细、原话摘录、证伪信号、跟踪清单、事后校验记录、引用、免责声明）；Track A、Track B 候选分层并列、标注证据等级（★★★/★★/★），不混排；S 级候选在分层表中单独标注并附七项判定清单的逐项证据；Track C 候选另层并列、标注错杀轨四档（C1/C2/C3/C4）与证据等级，同样不混排。创新药板块按统一评估框架输出单张总表（固定列：公司|价值驱动型|档位|四维评分|证伪信号），不按维度拆分子表。
- 各轨分层表固定含"增长驱动型"列（扩张/景气/周期/非经常，汉字标注）；机构拥挤度结论必须声明公募持仓数据滞后 1-2 个月、按最近两期趋势判断。
- 报告文件固定含"跟踪清单"一节（无核心候选时省略）；重检后更新档位并在报告中标注重检日期。
- 必须声明"概率判断、不构成投资建议"；前瞻结论绑定假设，假设证伪则结论失效。
- 不要把"业绩暴增"直接等同于"值得买"——阶段二的全部意义就在于区分这两者；也不要把"还没涨"直接等同于"有预期差"——Track B 必须回答"它为什么没涨"。Track C 输出必须声明左侧交易风险与分批建仓纪律；错杀判断本质是站在市场定价的对立面，四维排雷宁严勿宽，同时必须回答"市场为什么错了"——回答不了就降档。
