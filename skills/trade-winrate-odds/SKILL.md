# 交易胜率与赔率评估

对一个交易标的（+ 周期）做六维加权评分，**由评分结果判定多空方向**，再对该方向
计算胜率区间、赔率（盈亏比 R）、期望值 EV 与仓位参考。方向是评估的输出，不是预设。

核心公式：

- 综合分 `z = Σ wᵢ·sᵢ`，每维评分 sᵢ ∈ {-3(极空)..+3(极多)}，权重 wᵢ 随交易周期取表
- **方向判定**：`z ≥ +0.6` → 多头候选；`z ≤ -0.6` → 空头候选；`|z| < 0.6` → 观望
- 顺信号方向的胜率 `P = clamp(1 / (1 + e^(-0.6·|z|)), 0.30, 0.72)`，按数据完整度给区间
- 赔率：多头 `R = (目标 − 入场) / (入场 − 止损)`；空头 `R = (入场 − 目标) / (止损 − 入场)`
- 期望值 `EV = P·R − (1 − P)`（单位风险的期望收益）
- 仓位参考 `Kelly/4 = (P − (1−P)/R) / 4`，上限 25%

## 执行流程

### Step 0: 锁定评估对象

确认三项，缺失则向用户询问（用户不答时用默认值并声明）：

1. **标的**：股票名称/代码 + 市场（A 股/港股/美股）
2. **周期**：日内 / 短线(1-5 日) / 波段(5-20 日，默认) / 中长线(1-6 月)
3. **入场价**：默认取最新价；目标价与止损价按方向确定（见 framework.md）

**方向不在此步设定**。若用户自带方向（"我持有空单""我想做空"），记录下来，
在 Step 3 与评分方向对照；冲突必须在报告中明示。

### Step 1: 采集当前数据

按 [references/data-sources.md](references/data-sources.md) 的路由表采集六个维度的
**当前**数据（行情/量能、指标、新闻舆情、宏观、行业、估值位置）。规则：

- 只用本回合工具实际返回的数据；注明每项数据的截止时间
- 某维度数据取不到 → 该维记 `null`，不得编造；脚本会重归一化权重并加宽胜率区间
- 若本会话已跑过 `comprehensive-stock-analysis`，直接复用其结果打分，不重复采集

### Step 2: 逐维打分

按 [references/framework.md](references/framework.md) 的锚点标准，对六个维度各打
-3（极空）到 +3（极多）的整数分，并为每一分写一句证据（引用具体数据，禁止空泛）：

`technical` 技术面 | `volume` 量能 | `news` 消息面 | `macro` 宏观 | `industry` 行业 | `position` 价格位置/估值

### Step 3: 判定方向并计算

方向规则（脚本自动输出 `suggested_direction`）：

- `z ≥ +0.6` → **多头候选**：止损取下方支撑，目标取上方压力
- `z ≤ -0.6` → **空头候选**：止损取上方阻力，目标取下方支撑
- `|z| < 0.6` → **观望**：无统计优势，不算 EV，报告说明哪几维在打架
- **A 股个股做空受限**：空头候选 → 对持仓者建议减仓/离场，对空仓者建议观望，
  不计算空头 EV；港股/美股可融券或买认沽期权时再按空头计算

运行评分脚本（managed Python，零依赖）：

```bash
python3 <skill_dir>/scripts/calc_ev.py '{
  "horizon": "swing",
  "scores": {"technical": 2, "volume": 1, "news": 2, "macro": 0, "industry": 1, "position": null},
  "entry": 10.50, "stop": 9.80, "target": 12.00
}'
```

- 方向可不传：脚本从 `z` 给出 `suggested_direction`，从三价关系推断实际交易方向
- 也可显式传 `"direction": "long"|"short"`；与 `z` 方向冲突时脚本会输出警告
- 输出 JSON：`suggested_direction`、`z`、`win_rate` 及区间、`R`、`EV`、
  `grade`(A/B/C/D)、`position_pct`、`completeness`。`<skill_dir>` 为本 SKILL.md 所在目录

### Step 4: 输出评估报告

固定结构，保持紧凑（一屏内）：

```
## {标的} 交易评估（{周期} · {数据截止时间}）

**方向判定：多头（z = +1.10 ≥ 0.6）**  ← 或"观望（z = +0.30，多空信号混杂）"

| 维度 | 分数 | 权重 | 证据 |
|---|---|---|---|
| 技术面 | +2 | 25% | 站上 MA20，MACD 金叉，无顶背离 |
| ...（含取不到的维度，分数列写"缺失"）|

- **胜率 ≈ 66%（区间 61%–71%）**
- 入场 10.50 / 止损 9.80 / 目标 12.00 → **赔率 R = 2.14**
- **期望值 EV = +1.07R**，评级 **A**，仓位参考 ≤ 12.5%（1/4 Kelly）
- 失效条件：跌破 9.80 止损逻辑作废；{关键事件}落地前消息面分数有效
- 主要风险：1) ... 2) ...
```

方向为观望或空头（A 股）时，报告相应改为：观望理由 / 对持仓者与空仓者分别的建议，
不强行给出买点。末尾必须附：

> ⚠️ 胜率与赔率是基于当前公开信息的结构化主观估计，非客观概率，不构成投资建议。

## 纪律红线

- **方向由数据定**：不预设多空；用户自带方向与评分冲突时必须明示，不得默默顺从
- **给区间，不给确定数**：胜率必须带区间；完整度 < 1 时必须说明哪维缺失
- **EV ≤ 0 或评级 D → 明确建议放弃**，不为迎合用户而美化
- **数据必须本回合采集或来自本会话已有结果**，禁止凭记忆填行情/新闻
- 止损/目标价必须来自技术位或 ATR（见 framework.md），禁止拍脑袋
- 不向用户承诺收益；不输出"稳赚""必涨""必跌"类表述
