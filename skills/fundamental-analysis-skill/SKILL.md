# 基本面深度分析 Skill（draft-only，人工定稿必经）

## 铁律（违反即废稿）

1. **不产生任何规范化数字**：所有数字必须逐字引用底稿（fundamental_inputs JSON），
   禁止心算新数字——比率、增速、隐含价都由底稿 `derived` / `implied_returns` 给好；
   底稿没有的维度写「数据未采集 / incomplete」，**不猜**（§2.5）；
2. **事实 / 推断 / 观点三分标注**：底稿数字=事实；由事实推出的链条=推断（写明
   前提）；行业判断/护城河评分=观点。三者不得混排成一句话；
3. **每个结论附证伪条件**：「什么证据会推翻它」（对齐 event_assessments
   .falsification 口径），没有证伪条件的结论不许出现在报告里；
4. **禁用词**：必涨、必跌、建议买入、建议卖出、目标价、涨停、抄底、逃顶
   （同 config/llm.yaml review_gate.banned_words）；
5. **不做买卖建议**：本稿是分析底稿；仓位/排期决策归估值排期卡体系
   （fred-valuation-card-skill），报告末尾可指向排期卡但不得替它下结论；
6. **产出是 draft**：写 `reports/{symbol}/fundamental_{date}_draft.md`，
   人工改写定稿后去掉 `_draft` 后缀；系统不回读、不进信号链、不进日报；
7. **底稿 gaps 段必须如实呈现**：报告开头列「数据缺口」一节，逐条照抄
   底稿 `gaps`，不得淡化。

## 主输入：底稿导出

```bash
uv run python -m scripts.pipeline.fundamental_inputs <symbol>
# → reports/{symbol}/fundamental_inputs_{最新交易日}.json，八段：
#   meta / financials_multi_year / forecasts / valuation(含 implied_returns) /
#   pool_comps / events_summary / factor_snapshot / gaps
```

底稿过期判断：meta.data_cutoff.daily_bars 早于最近交易日 → 先跑采集 + daily 再导出；
财报期次落后于已知披露（看 events_summary.upcoming_calendar_30d 与最近公告）→
先补采 financials + balance_sheet/cash_flow/fin_abstract 再导出。

底稿覆盖不到的数据缺口（如池外竞争对手的精确估值），才允许回源
kimi-datasource 插件补取，且必须在报告中标注「非系统数据，待人工核」+ 来源。

## 三模块串行（不要跳步，每模块的产出是下一模块的输入）

### 模块 A：事实解读（只消费底稿）

逐段解读，全部数字引用底稿：

1. **盈利轨迹**：financials_multi_year 全期次的收入/归母净利同比序列——
   趋势是加速/减速/拐点？年报口径与最新季报口径是否一致？
2. **财务健康**（ derived 段）：净利率、ROE（注意 notes 里非加权口径注记）、
   资产负债率、有息负债、FCF、OCF/净利比；逐期看走向，不单看最新一期；
   财务状况结论只许三选一：稳健 / 走弱 / 恶化，且必须引用具体指标期次序列；
3. **盈利质量**：OCF/净利比长期 <1 或 FCF 持续为负 → 必须点名；
4. **预期与裂口**：forecasts 段 FY1–FY3 与 gap_check；裂口显著时写明
   「券商预期 vs 实际趋势」哪边更可能修正；
5. **估值位置**：valuation 段 pe_ttm 分位 + 恐慌低点对照 + implied_returns
   隐含回报区间表（明示这是「历史刻度 × 一致预期」的机械映射，非预测）；
6. **池内对比**：pool_comps 段——同行业码（industry_code 相同）的股票优先比，
   其余仅作全池参照。

### 模块 B：定性研判（可查背景，边界严格）

允许 WebSearch 补背景（商业模式、行业格局、监管动态），纪律同
message-tag-skill：**搜索只用于理解背景；搜到的具体数字不得当作事实写进报告**
（要引用就标「非系统数据，待人工核」并给出来源链接）。

1. **商业模式与护城河**（逐项打分 1–10，每项必须给证据，无证据的项打不出分
   就写「证据不足」）：品牌实力 / 转换成本 / 成本优势 / 网络效应 /
   专利或自有技术；与底稿 derived 指标互证（如高毛利+高 ROE 支持品牌/成本
   优势主张；指标走向与护城河主张矛盾时必须指出）；
2. **风险清单**（按危险程度从高到低排序）：行业颠覆 / 竞争 / 监管 / 财务
   （引用资产负债率、有息负债、FCF 期次序列）/ 事件面（引用 events_summary
   已生效标签与 pending 计数）；每条风险附证伪/缓解条件；
3. **增长潜力**：只许在一致预期覆盖的 FY1–FY3 内引用数字；更远期的判断
   一律标「观点」，并写明依赖的前提假设。

### 模块 C：对抗呈现（只重组 A/B 产出，不引入新事实）

1. **多空辩论**：多方与空方各列 3–5 条论据，每条标注来源模块（A-段号 /
   B-条目）——不许出现 A/B 里没有的事实；
2. **机构视角**：「机构可能买入的原因 / 可能回避的原因 / 关键跟踪变量」，
   跟踪变量必须可观测（下一期财报的哪个指标、哪个日历事项）；
3. **结论**：平衡总结 + 本报告全部结论的证伪条件汇总表。

## 输出格式

`reports/{symbol}/fundamental_{date}_draft.md`：

```markdown
# {name}（{symbol}）基本面深度分析 draft（数据截止 {daily_bars}）

## 0. 数据缺口（照抄底稿 gaps，逐条）
## 1. 盈利轨迹（模块 A.1）
## 2. 财务健康（模块 A.2/A.3）
## 3. 预期与估值（模块 A.4/A.5/A.6）
## 4. 商业模式与护城河（模块 B.1，打分表+证据）
## 5. 风险清单（模块 B.2，按危险程度排序）
## 6. 多空辩论（模块 C.1/C.2）
## 7. 结论与证伪条件汇总（模块 C.3）
```

## 对照示例

**合格写法**（数字溯源 + 三分标注 + 证伪条件）：
> 2026H1 归母净利同比 +46.3%（事实，底稿 2026-06-30 期）；ROE（累计口径）
> 17.4%（事实）。推断：盈利增速显著高于券商 FY1 一致预期（裂口 +X pp，
> 底稿 gap_check），若 Q3 延续该增速，一致预期存在上修可能。证伪条件：
> 2026Q3 归母净利同比回落至 FY1 预期增速以下。

**废稿写法**：
- 「毛利率约 35%」——底稿没有该期毛利率时自行估算（违反铁律 1）；
- 「护城河深厚，护城河评分 8 分」——打分未逐项给证据（违反模块 B.1）；
- 「当前估值偏低，值得关注」——「偏低」未引用 pe_ttm 分位数，且隐含买卖
  倾向（违反铁律 1/4/5）。

## 事实边界

- 底稿八段之外的事实一律不得出现；事件细节以 events_summary 的标签为准，
  需要原文时用事件 canonical_url 查（巨潮/交易所 PDF 为准）；
- 复权口径：底稿价格一律不复权（§3.4），不得与复权价混比；
- 分析窗口：底稿财报全历史（各股上市期不同，meta.data_cutoff 注记），
  引用早期期次时注意 published_at 为 NULL 的降级表头（2013–2022 期次
  available_at=入库时间，仅服务趋势分析）。
