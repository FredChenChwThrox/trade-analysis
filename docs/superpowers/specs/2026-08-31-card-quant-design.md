# 排期卡量化化：估值因子接入回测体系（设计 v0.1）

> 状态：draft，待人工 review。做完即停，未批准不动代码。
> 一句话：把「估值排期卡」的核心逻辑（PE 锚定、三档触发、证伪线）从人工判断
> 机械化为可回测、可监控的估值因子，接入现有 AKQuant 横截面评分链路。

---

## 1. 目标与边界

### 1.1 目标

- 在现有三因子横截面评分（momentum/volatility/liquidity，§11）之上**新增估值因子**，
  让"左侧低估买入"可回测、可量化验证。
- 产出**因子有效性检验**（IC / 分层单调性），回答："在这个 33 只池子里，低 PE 分位
  买入是否真的比高 PE 分位赚得多？"
- 为后续排期卡信号级回测（方案 B）与执行偏差度量（方案 C）打数据底座。

### 1.2 非目标

- 不做排期卡全流程机械化（情景矩阵 EPS×PE 属人工研判层，`build_schedule.py`
  机械档位已有弃用先例，见有友食品卡 §三）。
- 不替代排期卡生成/激活流程（LLM 只产 draft、activate/reject 必须人工，§5.6 不变）。
- v1 不引入盈利预期（forecast）因子——数据覆盖不全（海油/移动/百济/药明等
  forecast EMPTY），留待 v2。

## 3. 方案对比

### 方案 A：估值因子入库 + IC/分层检验（推荐起步）

**内容**
- `factors.py` 新增 `valuation` 因子 = **-pe_ttm 的 rolling 历史分位**
  （窗口 750 交易日 ≈ 3 年，与卡片 pe_scale 样本口径一致；rolling 分位只用当时及
  之前数据，天然满足点时语义 §2.1，无未来函数）。
- 复用 `build_factor_table` 链路扩展为四因子；新增 IC / 分层统计输出
  （`run_factor --ic`）。
- 产出：单因子 IC 报告（forward 20/60/120 日）＋ 五分层单调性表 ＋ 四因子 vs
  三因子轮动对比。

**优点**：改动最小（2–3 个 commit）、数据齐、直接回答"低估买入是否有效"。
**缺点**：不直接验证排期卡规则本身；33 只池横截面样本小，IC 噪音大
（结论定性为链路验证，延续项目纪律）。

### 方案 B：排期卡信号事件回测（并行观察）

**内容**：从激活卡片 JSON 提取三档价区/证伪线 → 事件序列 → 事件研究
（`signals/event_study.py` 已有先例），验证"T1 触发后买入持有 vs 沪深300"。

**优点**：直接验证你真实在用的规则。
**缺点**：激活卡片仅 6 张、历史锚不可重建（卡片多为 2026-08 生成，往前推的
"当时锚"是编造的）→ 样本极小，v1 只能验证近期，结论弱。

### 方案 C：执行偏差度量（后置）

**内容**：排期卡规则生成"应有交易"，与 `executions` 台账对比，度量滑点/延迟/
纪律偏差（`execution_log` 信号快照机制的量化延伸）。

**优点**：闭环你的"信号快照→执行留痕"体系。
**缺点**：依赖 A/B 先跑出规则基线；无基线时无意义。

### 推荐路径

**A（先做）→ B（A 完成后并行积累样本）→ C（有基线后再做）**。
A 最小可验证，B/C 数据会随激活卡片增多自然变好，不急于一时。

## 6. 风险与缓解

- **横截面样本小（33 只）**：IC 估计噪音大 → 结论限定"链路验证"，不做仓位依据。
- **价值陷阱**：低 PE 分位 ≠ 安全（盈利下滑推高 PE 被动位置）→ 与盈利轨迹组合是
  v2 方向（forecast 裂口），v1 单因子报告会显式提示。
- **分位前窗无分**：750 窗口下前 375 日（min_periods）无估值分 → 覆盖率下降可接受，
  报告里单列覆盖率。
- **估值 vs 动量天然负相关**：四因子合成会互相抵消部分信号 → 权重需跑后校准，
  D3 只是起点。
